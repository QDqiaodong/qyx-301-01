# qyx-301 线下沙龙客户适配场地智能推荐系统

## 项目简介
线下沙龙客户适配场地智能推荐系统，包含 Spring Boot 后端、Vue/Vite 前端、MySQL 和 Redis。

## 客户押金：冻结与分档退押
- **先冻结后占场**：客户口头看中场地后，确认时按场地日租金从客户押金账户冻结一笔押金；冻结成功需求才进入待办活动（已锁定）。冻结失败（押金余额不足等）当场报错并整笔回滚——需求不进待办、场地当天不被占用、不能开场，需先充值补足押金再确认。
- **取消活动按日退押（财务固定比例，销售不能手改）**：距活动日 ≥3 天取消全额退回；距活动日 1～2 天（三天内）取消只退一半；活动当天（及逾期）取消不退。退回比例完全由后端按日期分档计算，取消接口不接收任何比例参数。
- **解除/破裂全额退押**：销售解除锁定回炉重配、场地停用/涨价/拆设施导致锁定自行破裂，均非客户违约，冻结押金 100% 退回。
- **财务台账**：每一笔冻结、退回、没收、充值都落押金流水，前端「押金财务」页可逐笔查看；销售侧没有任何修改退回比例的入口。

## 开场当天值守（两岗签到才能开场）
- **两岗签到是开场条件（安保规定）**：每块场地当天有主值守、机动两个岗，两岗都签到齐全，场地才能从已锁定变成可开场；只签主值守、机动空着，场地停在已锁定，不能开场，也不能为了赶场绕过签到把已锁定直接改成可开场。
- **一岗一人**：同一岗位当天只能一人在岗；两人前后脚签同一岗，数据库唯一约束只放行一个，失败方看到「该岗已被占用」（含占用人）。撤岗后的空岗可重新签到。
- **中途撤岗**：主值守或机动撤岗导致两岗不齐时，已开场的退回已锁定、当天开场条作废；撤岗只动值守与开场状态，押金冻结保持不变（不结算、不退押）。
- **当天页**：「开场值守」页按活动日期列出当天已锁定场地的两岗与开场状态；签到、撤岗、开场后刷新的都是同一份持久化数据，再进当天页状态一致。
- 接口：`GET /api/duty/day?date=yyyy-MM-dd` 当天页；`POST /api/duty/signin` 签到；`POST /api/duty/withdraw` 撤岗；`POST /api/duty/open` 开场；`GET /api/duty/demand/{demandId}` 单需求值守视图。

## 场地改名：历史/流水/推荐结果与现名对齐
- **三处一起跟现名**：场地对外改名后，锁定历史、押金流水、推荐结果卡片上挂的场地名在同一份事务里全部同步成当前名称（仍锁定该场地的需求、踩点登记、值守签到、开场条也一并同步），现场对账不会把同一块场当成两块。只改场地卡片显示字、不同步历史和流水不算完成。
- **只改名，不动钱**：同步只更新场地名一列，已有冻结流水保留原金额、客户、退回比例与冻结/结算时间，绝不为对齐名称把旧冻结作废重冻一笔。
- **关页再开仍是同一份现名**：名称持久化在后端，重新进入历史页、押金财务页、推荐结果页读到的都是改名后的现名。
- **两人前后脚改名**：场地带乐观锁版本号，只放行最后一次对外名；持旧版本提交的一方收到 409，提示「场地信息已被其他人更新」并看到对方留下的最新名称，刷新后可按最新名再改。
